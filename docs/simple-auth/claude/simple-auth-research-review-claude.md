## 1. 오류 (Errors)

### 1.1 NICE 본인확인 설명 오류

**문서 내용** (섹션 4.1):
> NICE | 휴대폰, 신용카드 | REST API | 레거시 시스템 연동

**문제점**:
- NICE를 "레거시 시스템 연동"으로만 설명하는 것은 부정확함
- NICE평가정보는 현재도 주요 본인확인기관으로서 활발히 서비스 제공 중
- 휴대폰, 카드, 아이핀, PASS인증서, 공동인증서, 금융인증서 등 다양한 인증 수단 지원

**수정 제안**:
```
| NICE | 휴대폰, 신용카드, 아이핀, PASS, 인증서 | REST API | 종합 본인확인 플랫폼, 다양한 인증수단 지원 |
```

**출처**: [NICE API 플랫폼](https://www.niceapi.co.kr/), [NICE아이디](https://www.niceid.co.kr/)

---

### 1.2 인증서별 사용자 수 부정확

**문서 내용** (섹션 4.2):

| 인증서 | 문서 기재 | 실제/최신 정보 |
|--------|----------|---------------|
| 카카오 | 4,000만+ | 3,800만명 (2024년 기준), 시장 점유율 70% |
| PASS | 3,000만+ | 누적 발급 2,000만건 이상 (2020.12 기준), 최신 수치 불명확 |
| 토스 | 2,000만+ | 앱 사용자 2,408만명 (2025.03), 인증서 사용자와 구분 필요 |
| 금융인증서 | 1,000만+ | 정확한 최신 수치 확인 필요 |

**문제점**:
- 통계 수치의 기준 시점이 명시되지 않음
- "앱 사용자 수"와 "인증서 발급 수"를 구분하지 않음
- 카카오 인증서는 2022년 4월 4,000만 돌파 후 현재 3,800만명으로 감소

**수정 제안**:
- 통계 기준 시점 명시 (예: "2024년 기준")
- 데이터 유형 구분 (누적 발급 수 vs 활성 사용자 수)
- 시장 점유율 정보 추가

**출처**:
- [카카오 공식 뉴스룸](https://www.kakaocorp.com/page/detail/10998)
- [토스 설치 트렌드 2025](https://ko.accio.com/business/토스설치트렌드)

## 2. 누락 (Omissions)

### 2.1 본인확인기관 유형 분류 누락

**누락된 내용**:
본인확인기관은 4가지 유형으로 분류됨:

| 유형 | 대표 기관 |
|------|----------|
| **아이핀** | 나이스평가정보, 서울평가정보, 코리아크레딧뷰로 |
| **휴대폰** | SKT, KT, LG유플러스 |
| **신용카드** | 삼성카드, 신한카드, 현대카드, NH농협카드 |
| **인증서** | 금융결제원, 코스콤, 한국전자인증 등 |

**추가 필요 위치**: 섹션 1.3 "법적 근거" 또는 신규 섹션 생성

**출처**: [KISA 본인확인 지원포털](https://identity.kisa.or.kr/web/main/contents/M010-03)

---

### 2.2 금융인증서 상세 특징 누락

**문서 내용** (섹션 4.2):
> 금융인증서 | 금융결제원 | 1,000만+ | 클라우드 저장, 모든 은행

**누락된 주요 특징**:

| 특징 | 설명 |
|------|------|
| **유효기간** | 3년 (자동 갱신) - 기존 공인인증서 1년 대비 개선 |
| **인증 방식** | 6자리 PIN, 패턴, 지문, 생체인증 |
| **저장 방식** | 금융결제원 클라우드 서버 (HSM 장비 활용) |
| **별도 프로그램** | ActiveX 등 불필요 |
| **서비스 시작** | 2020.12.10 |
| **해외 이용** | 기기 등록 상태에서 가능, 현지 USIM 사용 시 제한 |

**출처**:
- [금융인증서 - 나무위키](https://namu.wiki/w/금융인증서)
- [금융결제원 통합포털](https://openapi.kftc.or.kr/service/financeAuthentication)

### 3.4 CI 생성 과정 상세 설명 보완

**현재 상태** (섹션 2.1):
> 생성 방식 | 주민등록번호 단방향 암호화

**보완 제안**:
```
주민번호 + 비밀정보(본인확인기관, KISA) → HMAC(일방향 암호화) → 64Byte → Base64 인코딩 → CI(88Byte)
```

**출처**: [CI, DI 차이점 - ihee.com](https://www.ihee.com/614)

## 4. 검증 완료 항목 (정확함)

다음 항목들은 웹 검색을 통해 정확성이 확인됨:

| 항목 | 문서 내용 | 검증 결과 |
|------|----------|----------|
| CI 크기 | 88 bytes | ✅ 정확 |
| DI 크기 | 64 bytes | ✅ 정확 |
| 전자서명법 시행일 | 2020.12.10 | ✅ 정확 |
| 민간인증서 시작 시기 | 2017~ | ✅ 정확 (카카오페이 인증 2017.06) |
| 공인인증서 → 공동인증서 명칭 변경 | 2020~ | ✅ 정확 |
| CI 범위 | 모든 서비스에서 동일 | ✅ 정확 |
| DI 범위 | 서비스별 상이 | ✅ 정확 |

## 5. 리뷰 요약

| 구분 | 건수 | 중요도 |
|------|------|--------|
| **오류** | 2건 | 높음 (NICE 설명, 사용자 수 통계) |
| **누락** | 6건 | 중간~높음 |
| **기타 개선** | 4건 | 낮음~중간 |

### 우선 수정 권장 항목
1. NICE 본인확인 설명 수정 (오류)
2. 사용자 수 통계 업데이트 및 기준 시점 명시 (오류)
3. 금융인증서 상세 특징 추가 (누락)
4. 비용 구조 정보 추가 (누락)
5. 본인확인기관 유형 분류 추가 (누락)
